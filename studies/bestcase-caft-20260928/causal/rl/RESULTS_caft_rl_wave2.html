CAFT in GRPO: four arms, five seeds

Can removing one direction from the model's activations during RL keep it from learning to cheat its own tests? Every arm trained for 200 steps on five seeds, and every run was then tested on held-out problems with the removal switched off and on.

    1What was tested

    h←h−(q·h)q

    At the output of layer 19 (of 36), the part of the activation h along a unit direction q is removed, at the last prompt token and every generated token, in rollouts, in the update pass and in the KL reference.

    ArmDirection removed during training
    • The model is rewarded when its code passes the tests. A hint shows it that it can define its own run_tests; a model that learns the hack writes a test that passes whether or not the solution is right.
    • 200 GRPO steps, 16 prompts × 16 answers per step, LoRA rank 32. Within a seed, all four arms share the LoRA init, the optimizer state and the data order, so each seed is a paired comparison.
    • Held-out test: 119 problems, 10 answers each, at steps 100, 150 and 200. Removal off loads the adapter alone and shows whether hacking was prevented or only hidden. Removal on generates as in training.

            6How sure are these results

            Two-sided Fisher exact test of each arm against the baseline, over the seeds evaluated. With five seeds per arm, only a difference of about four seeds can reach p < 0.05.

              7Next steps

              1. Fix the direction loss. Removing the joint direction lowers cheating mainly by stopping test writing, and that shortcut turns into hidden hacking during RL. A term that keeps honest test writing unchanged under removal would force the direction onto the cheating itself.
              2. Label every answer three ways: no test, honest test (rejects a wrong solution) and cheating test (passes a wrong solution). The evaluator already runs these checks, so this runs offline on the kept rollouts.
              3. Run longer and wider: 250 steps (hidden hacking is still rising at step 200), more seeds, a second model and more loopholes.
              4. Run the baselines in the same setup: the probe penalty, Advantage Modification and a generation-only hook.
              5. Close the leak: measure how much of q earlier prompt tokens carry, then remove q at every position.
