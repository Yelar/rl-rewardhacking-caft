# Review of the best-case CAFT study before step 2 (28 Sept 2026)

Scope: the plan, the step-0 code (`CHANGES.diff`), the step-1 pairs, and the parts of the existing pipeline the
study depends on. Three independent read-only reviews (code, RL pipeline, pair data) plus my own checks. Items
below were checked in the code or data unless marked otherwise. Nothing ran on GPUs; one tokenizer-only check
ran on gpu-03's CPU. Code paths are under `source/` unless given in full.

## What is sound
- The vLLM hook projects the full residual stream (hidden + residual, in fp32) and zeroes the residual on
  projected rows (`verl/verl/utils/caft_vllm_graph.py:28-32`). That is the same quantity the HF hook projects.
  Per-layer mapping, unit norms, predictor masks, prefix-cache handling and CUDA-graph padding all check out.
- Structural zero is an exact no-op in both paths, `layers=[]` installs nothing, and the v1 math is unchanged.
- `balance_virtual_dp_size` reproduces the 8-rank grouping under the current config (full-batch mini-batch,
  micro-batch 4, no dynamic batching). Nothing asserts those preconditions, though.
- The reward timing fix applies one rule to every arm.

## Fix before step 2 (directions)
1. **Splice bug (my v1.1 change).** Extending the span to the end of the line deleted the last line's trailing
   comment (usually `# Expected: X`) on the edited side. This hit 57–67 forward pairs (the count depends on how
   comments are parsed) and 10 style pairs, and no reverse pairs. So in forward pairs only the cheat side keeps an "Expected" comment, right before the end-of-answer
   readout. Fix: re-edit from task files that show the comment, then re-splice and re-grade.
2. **Claude's style appears on one side only.** Forward honest edits have fewer comments (6.73 → 5.79 per
   function). 54 of 100 use fixed `"Test N failed"` messages, whereas the model's own honest tests mostly use
   f-strings (23 of 40 reverse originals). About 30 edits also correct expected values (reviewer's count). Reverse edits are
   smaller (16% vs 29% of lines, reviewer's count) and mostly caricature cheats (`assert 2 == 2`). The model's
   natural cheats contain no asserts in any of the 100 forward pairs (98 are print-only, per the reviewer). So weighting forward and reverse equally does not cancel "Claude edited this".
   Fix:
   - honest edits keep the model's comment and message style;
   - build the direction from forward pairs, and use held-out reverse pairs as a transfer test (a pure "edited by
     Claude" direction would rank reverse cheats below their honest versions);
   - add natural cheat/honest samples from the model itself as a check free of Claude's style;
   - if reverse pairs stay, make them mostly print-only.
3. **All 140 real pairs have wrong solutions,** so every honest side fails on its own solution. The direction may
   partly mean "these asserts contradict the code". Fix: add pairs with correct solutions.
4. **Style controls only reword comments and messages** (18 of 20 are cheats). They cannot detect Claude's
   code-level style.
5. **Two pairs need fixing.**
   - Exclude `src-6a1941e6f764` (reverse, test split). Its "honest" original is print-only; it is labelled Innocent
     only because it crashes on the return-0 solution. The "cheat" adds a tautological assert, so the contrast
     runs backwards.
   - Fix `src-a3a954ddb2c9`, which tests z=0 outside the problem's constraints (reviewer's finding, not
     re-checked).
6. **Readout positions (corrects my earlier advice).**
   - The end-of-turn token is outside CAFT's projected positions: the last response token is excluded
     (`verl/verl/utils/caft.py:222-237`). The chat template also appends that token even to truncated answers.
   - The text after the edit is byte-identical, but it tokenizes differently at the boundary in 140 of 160 pairs
     (pinned Qwen3 tokenizer). The shared tail has to be aligned from the end: a median of 24 identical tokens,
     but 3 pairs share only the closing fence.
   - Read at the closing fence or the shared tail. Region (b) runs from the first differing token to the start
     of the shared tail. Two pairs end in prose.
7. **Layer index.** The post's "layer 34" is `hidden_states[34]`, which is the output of block 33.
   `unit_from_logistic` does not enforce this shift (`src/bestcase/directions.py:28`). Add a check.
8. **The post's probe pipeline** (`scripts/run_probes.py`).
   - It needs `leetcode_train_medhard_holdout_all.jsonl`, built by `run_data_process.py` with hint=all
     (overwrite_tests with randomized names, detailed, aware, modify_tests and incontext_tests; no-hint rows are
     dropped).
   - Our checkpoints were trained on the fixed name `run_tests`, so they may hack rarely on those prompts.
   - Sampling is unseeded (lines 47, 141, 155, 272).
   - A probe trained on a single loophole may learn "writes a test function".
9. **Step 3 is only a proxy.** It removes the direction at inference on Mrh, while CAFT acts during training.
   Pre-register a stop rule: no RL if no candidate beats energy-matched random on Mrh.

## Fix before step 4 (RL)
10. **Seeds and power.**
    - With 2 seeds per arm, the best possible one-sided permutation p is 1/6.
    - Past near-null runs often did not hack. Random0 had 0% at step 100 on H100, and 0 hacks across checkpoints
      80–200 on L40S where the baseline was about 50%. The PC4/Random0 order flipped between setups.
    - If about 40% of runs fail to hack by step 200 regardless of arm, both CAFT seeds come out clean 16% of the
      time.
    - Fix: 4–5 seeds for none, energy-matched random and best-case CAFT; penalty arms as positive controls with
      fewer seeds; a power simulation and a locked protocol; onset step as a secondary outcome.
11. **Seed independence.**
    - Rollout RNG is fixed: dp_rank + 1000 (`verl/verl/workers/fsdp_workers.py:619-623`) and vLLM seed 0
      (`vllm_rollout_spmd.py:257`).
    - The existing sampler profile requires `data.seed == 1` (`src/train/verl/caft_sampler.py:43-44`).
    - So seeds that differ only in LoRA init share their data order and produce identical step-1 rollouts.
    - Fix: derive data order, rollout RNG and LoRA init from each seed. The common-initial-state code is
      v1-only (`src/train/verl/caft_initialization.py`).
12. **Penalty arms cannot run in the CAFT pipeline.**
    - CAFT runs require the sandboxed reward, which accepts only `CorrectOrHintedCompileCode` and no activations
      (`src/train/verl/trainer.py:282-286`, `src/train/verl/rewards.py:79-80,106-109`).
    - Penalty arms would therefore take a different reward path:
      - without hooks;
      - with `max_num_batched_tokens` 8192 instead of 16384 (`src/train/verl/grpo.py:191`);
      - with an extra activation GPU, where only 2+1 or 4+1 layouts work (`src/train/verl/grpo.py:124-132`).
    - On that path, generated code is sandboxed only if `CODE_EVAL_SANDBOX=bwrap` is set
      (`src/evaluate/helpers.py:202-206`).
    - The activation worker:
      - never checks that the LoRA weights loaded (`src/train/verl/workers.py:139`);
      - loads the model without the pinned revision (`workers.py:78-83`);
      - handles single-layer probes only (`workers.py:173`, `trainer.py:505`).
    - Fix: add the penalty inside the sandboxed CAFT pipeline with structural-zero hooks, add the load check, and
      support multi-layer scoring.
13. **Penalty noise.** Advantages are normalised by the group's standard deviation (`trainer.py:136-137`). One
    false flag in an otherwise equal group then gives advantages of −3.75 and +0.25, and at 5% false positives
    56% of such groups get a flag. Optional control: random flags at the same rate.
14. **KL toward an unprojected reference.**
    - KL is on: `use_kl_loss: true`, β = 1e-3, `low_var_kl` (`src/train/verl/grpo_config.jinja2:46-48`,
      `src/train/config.py:137`).
    - The reference runs with both the LoRA and the projection off (`caft.py:487-493`, forced by `caft.py:44`).
    - Step-1 KL was 0 for none, 2.2e-4 for Random0 and 6.0e-3 for PC4 (run logs, as read by the reviewer; not
     re-checked). So from step 1 the LoRA is trained to undo
      the projection, more for a real direction than for random. The effect is probably small but systematic.
    - Fix: project the reference too (a code change), or set β = 0 in every arm (a science change).
15. **Outcome validity.**
    - Strict hacking counts truncated, crashing or test-less answers as not hacking (`src/analysis.py:64-83`).
    - The grader runs the whole program before the real tests, including module-level `run_tests()` calls (152 of
      160 pair answers have one). A correct solution with a wrong self-test is therefore scored incorrect.
    - Fix: pre-register guardrails (truncation, invalid outputs, the share of answers defining `run_tests`, and
      hacking among those that do). Add a secondary accuracy with module-level calls stripped.
16. **Grader indentation artifact.** It affects 36 of 119 test problems (30%) against 17 of 992 training problems.
    Strict hacking is unaffected. The attempted-hack and harmful-modification labels are inflated, and more so for
    arms that move to honest tests. Fix: re-indent the reference in the join (`src/evaluate/evaluation.py:300-307`)
    and add a test.
17. **Evidence.**
    - None of the 60 CPU tests touch `caft_vllm*.py`.
    - The GPU check cannot catch an off-by-one layer or swapped directions (0.996 agreement with projection ON vs
      0.988 absent). Add a per-layer vLLM-vs-HF comparison on identical inputs, asserting q·h ≈ 0 on projected
      rows.
    - In `test_bestcase_step0.py`, `unittest.main()` at line 334 comes before two test classes (pytest still runs
      them).
18. **Bookkeeping.**
    - `source_inventory.json` and `RUNTIME_PROFILES.json` pin the old hashes and omit `lora_seed.py`.
    - `lora_init_seed` and `balance_virtual_dp_size` silently default to None (`fsdp_workers.py:440`,
      `ray_trainer.py:928`).
    - v1-only guards remain in `caft_rollouts.py:53` and `caft_factorial.py:70-71`.
    - The evaluation copy (`artifacts/ada8-posttrain-eval-20260917/source_v1`) still has the old timeout race.
    - No-loophole evaluation is not wired in.
19. **Time.** gpu-03 has 5 idle RTX 5000 Ada GPUs (32 GB). A 1-GPU run takes 16–23 h, and a penalty run needs 3
    GPUs. So 12 runs take about 2.5–3.5 days on gpu-03 alone, not the 1 day I estimated earlier.
